# 모델 체이닝 노드 편집기

개별 모델 노드를 자유롭게 추가·배치하고 연결점으로 실행 흐름을 구성한다. 새 노드는 고아 노드로 추가되며, 기존 노드의 위치나 연결은 바꾸지 않는다.

## 편집과 저장

- 노드 제목을 끌어 위치를 변경하고, 본문을 선택해 모델과 프롬프트를 편집한다.
- 출력 연결점에서 입력 연결점으로 드래그해 연결한다. 한 노드의 분기와 여러 노드의 합류를 지원한다.
- 연결선을 클릭하면 색과 굵기로 선택을 표시하고, 선 위와 상단의 연결 끊기 버튼을 제공한다. Delete/Backspace로도 연결을 끊을 수 있다. 연결선 끝을 드래그하면 다시 연결한다.
- 연결선의 투명 클릭 영역은 확대·축소와 무관하게 화면상 28px을 유지한다. 기본 선 스타일은 CSS에 두어 선택 강조가 인라인 스타일에 가려지지 않게 한다.
- 노드를 삭제하면 해당 노드의 연결과 위치만 제거한다. 마지막 모델 노드도 삭제할 수 있으며 기본 응답 모델은 삭제하지 않는다.
- 고아 노드의 프롬프트, 기억 설정, 모델 바인딩, 위치와 고아 노드 사이의 연결도 저장한다. 고아 노드만 있거나 기본 응답 모델만 남아 있어도 저장할 수 있다.
- 최대 모델 노드 수는 기존과 같은 32개다. 레이어 개수에 따른 편집 제한은 없다. 자기 연결, 중복 연결, 순환 연결, 존재하지 않는 노드의 연결은 UI와 API에서 거부한다.
- 저장 중에는 노드 이동·연결·삭제를 비활성화한다.

## 데이터 호환성

- `layers`는 기존 에이전트 설정과 식별자, 이전 버전의 `phase` 값을 보관한다. 새 편집기와 실행기는 `phase`를 역할 판정에 사용하지 않는다.
- 선택적인 `graph`에 `edges: { id, source, target }[]`와 `positions: Record<nodeId, { x, y }>`를 저장한다. 노드 ID는 `agent:<agentId>`와 고정 `main-response`다.
- DB의 기존 `steps_json` 안에 버전 3으로 저장하므로 별도 SQL 마이그레이션이 필요 없다.
- `graph`가 없는 기존 데이터는 사전 레이어 → 기본 응답 → 후처리 레이어로 변환한다. 인접 레이어의 모든 에이전트를 연결해 기존 순서와 병렬 실행을 보존한다. 명시적인 빈 `edges`는 자동 연결하지 않는다.
- 복사와 JSON 가져오기는 노드 ID를 재발급하고 연결 참조·위치 키를 함께 변경한다. 내보내기에는 고아 노드와 배치도 포함한다.

## 실행 규칙

실행 계획은 프런트엔드와 서버가 공유하는 `shared/src/model-chain-graph.ts`에서 계산한다.

1. 화살표 방향과 관계없이 기본 응답 모델과 같은 연결 묶음에 속한 모든 노드를 실행한다. 별도의 연결 묶음과 완전히 끊긴 노드만 고아 노드다.
2. 전체 연결 묶음의 의존 관계를 위상 정렬하고 준비된 같은 단계의 노드를 병렬 실행한다. 메인 모델과 나란히 실행 가능한 옆 가지도 포함한다.
3. 각 모델 노드는 연결된 선행 노드의 결과만 받는다. 다른 분기의 결과는 합류하기 전까지 섞지 않는다.
4. 기본 응답 모델보다 앞선 노드의 결과는 메인 요청에 전달한다. 기본 응답을 선행 관계로 가진 노드는 현재 응답과 연결된 선행 결과를 받아 `응답 반영 방식`에 따라 결과를 만든다.
5. 비활성 노드는 호출하지 않지만 연결 경로는 유지한다. 고아 노드는 모델 호출과 기억 읽기·갱신을 모두 생략한다.

`pre`/`post` 값은 기존 저장 데이터와 요청 디버그 기록을 읽을 수 있도록 내부 호환 필드로만 남긴다. UI와 실행 역할은 이 이름으로 나누지 않는다.

## 검증

- 웹 전체 테스트 95개, 공유 계약·실행 계획 테스트 8개, 서버 모델 체인·계약·API 통합 테스트 26개 통과.
- 타입 검사, 린트, 서버·웹 프로덕션 빌드 통과.
- 격리된 테스트 DB와 Echo 모델로 브라우저에서 노드 추가·드래그·연결·Delete로 연결 해제·고아 노드 저장 후 재열기·복사·마지막 노드 삭제·기본 응답만 남은 체인 저장을 확인했다.
- 저장 전후 노드 좌표와 고아 노드의 프롬프트가 동일하며 브라우저 콘솔 오류가 없음을 확인했다.
